# Maze Escape: The Forgotten Labyrinth

2D Java game built around OOP (Epitech project B-OOP-301).

The player searches a randomly generated maze for the key that opens the door to the
exit. Three kinds of enemies hunt him, items help him survive, and one enemy blow kills him.
Three levels, each bigger than the last.

## Features

- JavaFX window with a main menu, Game Over and victory screens.
- Real-time movement: the player (3 tiles/s) is faster than the Chaser (2 tiles/s),
  unless a Leech slows him down.
- Random maze from a seed, with loops; the exit sits behind a locked door.
- Key placed by breadth-first search in the far half of the maze; it moves on every restart.
- 3 enemies: Chaser (BFS pathfinding, gives up after 15 s out of sight),
  Bomber (explodes on contact), Leech (halves your speed for 10 s).
- 5 items: Key, Speed Boost, Shield (8 s of invincibility), Taser, Time Stop.
- 3 levels (13x13, 15x15, 17x17), more enemies each time.
- An original animated stickman with a red scarf: he breathes, blinks and his scarf
  flutters even when he stands still.
- HUD with level, key, items and status (slowed, shielded, enemies frozen).
- Automatic save at the start of each level; a broken save never crashes the game.
- 103 unit tests and a JaCoCo coverage report.

## Controls

| Key | Action |
|---|---|
| Z Q S D or arrows | Walk |
| T | Taser (removes an attached Leech) |
| F | Time Stop (freezes enemies 5 s) |

## Build, test, run

Needs Java 17 or newer (JDK) and Maven.

```
mvn -q compile          # build
mvn -q test             # run the tests (prints nothing when everything passes)
mvn javafx:run          # play
```

Test coverage report (generated by `mvn test`): `target/site/jacoco/index.html`.

Documentation (Javadoc): `mvn javadoc:javadoc`, then open `target/reports/apidocs/index.html`.

Headless console version (proves the logic runs without any GUI):

```
mvn -q compile exec:java
```

### Docker

Docker runs the tests in a clean container: same Java and Maven for everybody, nothing to
install but Docker. The game window itself runs on your machine (`mvn javafx:run`).

```
docker build -t maze-escape .
docker run --rm maze-escape
```

On Windows with WSL, start Docker Desktop and enable *Settings → Resources → WSL integration*
for your distribution first.

If `make` is available: `make build`, `make test`, `make run`, `make docker-test`.

## How we worked

- The Game Design Document fixed the rules first; it is updated whenever the code changes a rule.
- Game logic has no JavaFX code: maze, items, levels, save, timers and the stickman's pose are
  tested headless, then JavaFX draws them.
- One branch per member (`rugema`, `naim`), small commits with prefixes
  (`feat`, `fix`, `test`, `docs`, `refactor`, `chore`), merged regularly.
- Each of us can explain the other's code.
